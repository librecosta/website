# The Expanse · P1-G0 美术基线

采集于 2026-11-11，场景基于 `develop` 的 `bd19c46`。第一幕的尺度已经成立。浅谷两侧压住城市底部，中央轴塔把视线拉进巨环，飞艇和小型车流提供了大小参照。优先补足轴塔中段的真实结构深度，以及巨环近侧节点的连接关系。两处在终景里已经占据足够的画幅，细化后也能在原镜头中检验。

复拍时执行 `pnpm check` 生成静态导出，再用 `pnpm preview` 打开 `/lab/expanse?debug=1`。页面从顶部载入，镜头保持中性指针偏移，天空用最终合成，风沙用默认输运，关闭声音和观测卡。首次可见后约 1.1 s 定位。除 S0 保持顶部外，滚到 `round(innerHeight × (0.4 + 5 × p))`，等调试面板的平滑进度追上原始进度。S0–S3 稳定后再等约 0.4 s，S4 在终句阶段取样，S5 等三个品牌元素的透明度都达到 0.999。复拍时只隐藏调试面板，保留实际页面构图。风沙读数以约 0.25 s 间隔更新，运动对比用截图前后的城市时钟范围匹配相位。

本地 `.local/p1-g0/` 保存 `desktop-S0–S5.jpg`、`mobile-S0/S2/S4/S5.jpg`、两档总览和对应 JSON。JSON 包含原始与平滑进度、相机 XYZ、XYZW 四元数、FOV、缓冲区尺寸、动态时钟、品牌状态及采样前后统计。移动端 S2 实测 `u=.45634`，S4 截图期间 `u=.99998–.99999`。另有 S0–S2 同机位关风对照，以及 S3 同机位约 6 s 后的运动对照。

## 美术问题与优先级

| 机位与具体对象 | 观察与可能原因 | 优先级 / 阶段 |
| --- | --- | --- |
| S0 · 上方云层、左坡、远城 | 暖色风幕把低云、沙脊和远城压进相近明度。关风后冷灰天空、右坡亮面和遗迹背光面重新分开，说明当前风幕的影响大于天空底色。保留开场遮蔽，先试降低高仰角风幕的不透明度，把较高的浓度留在谷底和近镜。 | 高 · G3 |
| S1 · 右坡风纹、中央暗弧 | 正常画面里右坡风纹接近一条软亮带，关风时纹理能读出来，但长波纹连续越过坡脚，谷底暗弧依然近似一条锐边。以坡向和地形曲率区分迎风坡细纹、背风沉积和谷底输运。用关风对照检查暗弧附近的坡度、阴影与纹理过渡。 | 中 · G2，风幕在 G3 复拍 |
| S2 · 信号塔天线、面板和沙埋线 | 倾斜轮廓和真实遮挡交代了埋深。关风后仍可见天线、壳体和暴露边缘共享近似的棕色响应，坡面切过右下壳体时缺少积沙厚度变化。当前 GLB 几何使用单一高粗糙度石材。优先区分天线金属、磨蚀壳体和下沿积沙，在背风脚与凸缘各做一处可读的沉积过渡。 | 中 · G2 |
| S3 · 近侧环梁、径向节点、飞艇与车流 | 双轨、断口和巨大内空已经能建立比例。近侧接头多呈重复卡箍，轨间缺少清楚的连接深度和开口。两艘飞艇与轨道的慢速相对运动有效。约 6 s 后的对照仍可读出环段和飞艇的独立位移，小型车流却常读成悬在同一层的灰点。先明确梁与节点的连接，再用楼体遮挡和既有路线的高度差表现车流层级。 | 高 · G1 环梁，G3 车流 |
| S4 · 中央双翼轴塔、塔脚、左右楼群 | 塔身主要靠两条亮线与大块灰面辨识，顶部开口被前环投影及冠雾压弱，塔脚与台地在低雾中连成一块。街区高低梯度成立，近侧仍以同类切角窄塔为主。先给塔身中段做可见的承重截面和空腔，给塔脚留可辨的转接层。用不同占地、退台和连桥组织中层楼群。之后再调壳体与内构的明暗和雾层。 | 最高 · G1 轴塔与街区，G2 材质，G3 雾层 |
| S5 · 品牌文字与城脚重叠区域 | 桌面标题落在塔脚和中层楼群上，现有浅雾提供了可读的背景。移动端保留完整环形轮廓，巨城在屏幕中段缩成窄带，塔的次级结构更容易消失。G1 的细节优先放在标题上方和轴塔侧面。最后用两档全幅复看字幕、品牌文字、塔脚以及环内负空间的主次。 | 中 · G4 |

## 性能与资源

本机为 Windows 10 22H2、Ryzen 7 5800H、约 32 GB 内存。Codex 内置 Chromium 157 前台运行，WebGL2 实际使用 ANGLE D3D11 和 AMD Radeon 集成显卡。用本地无压缩、禁 HTTP 缓存的生产静态导出。移动档是同机的窄视口采样，手机硬件、触控以及高 DPR 尚待实机验证。

帧间隔取连续两次实际 R3F 渲染的时间戳差，按最近秩计算 P50/P95。S0 和 S4 分别在固定镜头持续播放 6 s，滚动样本用原生页面滚动 4 s 前进、4 s 返回。静止样本在减少动态效果切换稳定后观察 6 s。Draw Calls 和 Triangles 来自 `WebGLRenderer.info.render` 的逐帧快照，Geometry 和 Texture 为驻留计数。冷启动的阴影更新与持续帧分开。GPU 使用独立重复窗口，在 WebGL2 `EXT_disjoint_timer_query_webgl2` 下从首个清除或绘制命令计至该帧最后一次同步 GL 提交。异步读取，两个档位均无 disjoint，数值覆盖所提交的 GPU 工作。

## G1 多结构组合方案

现有 [城市生成器](../../src/components/expanse/skyline.ts) 已经把轴塔及台地合并为一组静态几何，巨环是独立的运动网格。400 栋街区建筑按内外区和高矮分成四批实例。保留这三个渲染层次，先用实体遮挡和负空间证明构件关系，再处理表面细节。

| 对象 | 值得真实建模的部分 | 适合程序化复用的部分 |
| --- | --- | --- |
| **A · 中央轴塔** | 保留两片渐收主翼的外轮廓与顶部透空间隙。先做一段中部剖面，从承重翼和后置脊柱出发，在翼外偏置壳板，做出带侧壁和后壁的深槽。让两三处有明确标高的转接平台接入内构，选择性跨过空腔，保留连续的纵向暗面。塔脚用基座、转接肩和翼根建立可追踪的受力路径。主翼与空腔的交接、塔脚转接、一个临空检修平台值得独立雕琢。 | 纵向肋、壳板分段、平台格栅、设备舱和收口可按固定标高与截面复用。微型缝线、紧固件和编号由材质或烘焙承载。先做当前 S3/S4 能辨认的中段，再用局部近视图检查槽深和遮挡。 |
| **B · 环形巨构** | 先做 S3 近侧一个梁段及断口。让主箱梁有可见的截面厚度，把双轨分成外承载轨和内侧下挂导轨，用跨越轨间空隙的径向横梁承托。在少数转运节点做有厚度的托座、端盖和维护平台，区分环段端部接头、中间支撑和大型转运节点。保留八段开缝、中心负空间、与轴塔的可见分离和 180 s 慢转。 | 用相同截面沿既有弧线生成梁和轨，按切线和半径放置三类节点。标准肋、支架与走道从同一模块复用，整环仍随现有枢轴合并运动。既有环形观测锚点随转运节点保持一致。 |
| **C · 城市楼群** | 先做三种可在 S4 认出的轮廓样板。外区低矮工务台采用宽基座和侧翼，入口建筑采用双体加门洞或连桥，内区高塔采用退台与偏置设备层。保留建筑密度、台地间隙和向中轴抬升的高度梯度。 | 为基础、主体、顶部、侧翼、连桥和设备设定连接面。按地块和功能确定组合，再用固定种子选取尺寸与朝向。每种组合预合并为少量 archetype 并用 `InstancedMesh` 批量绘制。普通远景楼栋优先按轮廓选简化档，合并细部网格，避免逐栋逐部件出批。 |

轴塔和环梁先按共享顶点色及发光属性合并静态部件，保留独立的运动网格。若轴塔的翼壳交接或环梁转运节点在 Blender 更容易做出可靠厚度，选一个样件验证优化 GLB 路径。对比索引化网格、材质槽与传输体积，确认导入后保留大气、发光和定位，再决定是否替换程序样件。只有近视图确实看得到的部位才加更高 LOD，S3/S4 和移动档优先保住外轮廓、开口和接点。

## G1–G4 顺序

1. **G1 · 构造。** 先做轴塔中段的翼壳、后置脊柱、深槽和第一处转接平台，用 S4 看明暗面与空间深度。随后用 S3 做一个双轨梁段及有开口的转运节点，再推广到整环。最后在一侧台地试三类楼群轮廓。复看 S3/S4 的尺度、环内留空、航线净空与两档帧时间。
2. **G2 · 材质与地表。** 依据 G1 形成的结构分工区分外壳、骨架、轨面和积沙。先用 S2 做信号塔的金属、磨蚀壳体与沙埋交界，再用 S1 对照迎风坡、背风脚与谷底。
3. **G3 · 光、雾与运动。** 用 S0–S2 将低空浓度与高仰角可见度分开，用 S3/S4 恢复塔脚台地层次和冠部的开口。用同机位不同城市时钟复看两艘飞艇、环段和近侧车流，优先利用既有速度差和遮挡。
4. **G4 · 正式构图。** 对照六组全幅和移动抽查，重点复看 S4 到 S5 的视觉重心、品牌文字背景以及城市新增结构的可读性。保留电影字幕、品牌揭示、观测卡和仪表的现有叙事节奏。
