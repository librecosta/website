# 程序化环境研究 · P1-A

本文按阶段保留技术实验。旧硬壳、天空、风沙与光照调试的退役说明及截图见 [The Expanse 历史归档](../archive/expanse-legacy/README.md)，现行调试入口见 [仓库 README](../../README.md)。

2026-11-06。目标是先确认荒原的空间灰模；以下是技术取舍，不冻结世界观、建筑母题或最终镜头。没有引入 Houdini 运行时，也未下载第三方设计资产。

## 研究与取舍

| 主题 | 技术思想与优缺点 | LibreCosta 的采用方式 |
| --- | --- | --- |
| 人工 Massing | 先控制山体占地、高低关系与围合空间，再增加细节，比全域叠噪声更容易保持构图；需要明确的人工空间决策。 | P1-A3 修订以中轴、横截面和 3 条连续坡脊建立相接沙体，左岸叠加 2 处重叠的横风丘面。局部丘面服从连续基底，不沿纵深复制孤立丘包。 |
| Heightfield 与多尺度噪声 | 二维网格保存高度，便于分层与重采样；不能表示悬挑、洞穴和同一平面坐标上的多层地表。细节尺度过小而振幅过大容易产生尖峰。 | CPU 上生成确定性高度，转换为真实索引网格并重算顶点法线。大尺度形体优先，三层低振幅平滑值噪声只补自然变化，不做侵蚀模拟。 |
| 局部生成遮罩 | 遮罩限制某层效果的作用范围，便于分开调整道路、盆地和山脊；遮罩过硬会产生突兀台地。 | 通道随谷地弯曲，保留 12% 丘脊起伏，横向渐变加宽至 440 单位以避免丘面相接后出现过陡内坡。实体仍按旋转后脚底采样并下沉，不靠换色埋藏。 |
| 程序化与模块化 | 先定义构件与空间规则，再重复组合；可迭代、可复现，缺点是容易显得等距机械或像随机城市。 | P1-A4 反馈后保留外倾双板：`ideal` 记录基准，`disturbed` 记录手工偏移、沉降与倾斜。近处左段横卧、右段内倾，远处碑林与主碑采用同一种收分几何。 |
| InstancedMesh | 同几何、同材质的不同变换可合并提交；不能自动解决材质多样性、实例级剔除或过大批次包围范围的问题。 | 当前 4 个长方体共享一批，5 座远碑与主碑共享一批凹槽台体，共用灰材质。不创建空实例批次，不建立空间分块平台。 |
| 空气、光与几何 | 雾降低远处对比，日光显露体量；过浓的雾或过强环境光会掩盖构图缺陷。 | 用基础 DirectionalLight、HemisphereLight、阴影与线性 Fog；近处保持清楚，远方融入同色天空。不加 Bloom、粒子或体积云。 |
| 离线／实时边界 | 离线适合独特结构和复杂静态细节，实时适合参数布局与响应视口；烘焙材质不等于可直接迁移整套离线光照。 | 本轮全部是基础几何和灰模材质；Blender 留待重要独特资产与必要烘焙，整体构图通过前不做高模与精细纹理。 |

地形的分层、遮罩与限制来自 [SideFX Heightfields](https://www.sidefx.com/docs/houdini/heightfields/)，先 Massing 后细节与逐步重采样的思路来自 [Terrain Creation](https://www.sidefx.com/docs/houdini/heightfields/creation.html)。我们采用其制作逻辑，不复制 Houdini 的噪声或侵蚀实现。

实例化的 API、矩阵更新与包围体职责以 [Three.js InstancedMesh 文档](https://threejs.org/docs/pages/InstancedMesh.html) 为准。Crosswire 文章讨论的是 2023 年的实现限制，不能据此断言当前 Three.js 完全不支持实例网格包围体剔除。

## 当前实现与待验证事项

- 参数源：`src/components/expanse/parameters.ts`；地形、埋藏与路径算法：同目录 `world.ts`。固定种子只控制地貌细节，所有巨构布局人工配置。
- 只有 `/lab/expanse` 初始化一个客户端 Canvas，正式首页维持原状；品牌、无障碍标题与空间描述独立于 WebGL。正常画面没有观察点、研究说明或额外导航；没有外部模型、纹理或天空资产请求。
- 移动端使用较低地形网格密度和 DPR 上限。相机共用同一路径，以 2:1 参考画幅做 contain 取景：窄窗保留水平范围，整体缩小并增加上下视野。竖屏主体占比下降是明确取舍，不靠固定的移动端 FOV 增量裁切构图。桌面模拟移动视口不等于真实手机性能或触摸手势验证。
- **待验证／后续范围**：真实手机 GPU、触控板／触摸硬件和功耗；更复杂地形下的分块与 LOD；最终高速镜头；需要更复杂大气时的成本。本轮仅验证现有受控路径。

本轮浏览器观察与仍存构图问题记录于 [expanse-blockout.md](expanse-blockout.md)。后续按 **地形 → 巨构布局 → 镜头构图 → 空气与光线 → 正式材质** 迭代。

## P1-A3 首轮观察（历史）

- 原有单层 Massing 的起伏不足以建立谷中视角。将中轴、谷底高程、横截面、分层丘脊和局部覆沙拆开后，浏览器能读出左右包裹与逐层遮挡；仅增加噪声振幅没有用于解决此问题。
- 近丘过高会吞掉中景，低矮残片靠近镜头后也会显得像完整方块。本轮降低右侧近丘、拓宽通道渐变，并将残片露出高度压到约 23–37 单位，保留主体远近层级。这些是当前视角观察，不是适用于所有布局的最优参数。
- 相机位置相对同一谷地中轴采样，眼高相对真实地形高度。桌面与移动网格分别做轨迹净空检查，避免降采样后通道局部抬高而穿地；前 20% 的位置、注视点、视角和滚转保持不变。
- 用路由内 DOM 的 `:has()` 选择器隐藏根滚动条外观，保留原生文档高度；底部细线读取原生进度，GSAP 的短暂追随只影响相机进度。没有拦截 wheel 或用进度条接管输入。

## P1-A3 反馈后的修订

- 首轮独立椭圆丘脊仍产生重复的凹口，不能把“一个高度网格”误认为视觉上已经连贯。当前坡脊沿纵深连续插值，彼此平滑融合；两处交叠丘面在连续沙体上塑形，保留层次，避免每个丘包单独降到谷底。
- 左侧两条坡脊间用两种实际地形网格采样连接带；最低连接高差约 97.96 单位，高于谷底。此数值是当前布局的有限采样结果，不是对任意参数的连续性证明，也不能替代画面评审。
- 前 20% 静止段会让用户误以为没有响应。已取消，起点前移，首端使用非零位移导数，短暂进度追随改为 0.18 秒；有效滚动长度为首次视窗高度的 3 倍。
- 固定垂直 FOV 会在窄窗裁去两侧。按参考画幅计算垂直 FOV 后，468 次可见建筑顶点对照均保留了原水平投影与画幅内位置；仍需浏览器检查取景，不能把这个投影检查当作艺术验收。
- 仅修正 FOV 还不够：若文档始终以实时 vh 计算总长度，改变窗口高度会改变同一 scrollTop 的旅程进度。当前将本次访问的原生滚动距离固定为像素，只让粘性画布跟随实时视窗高度；无需在 resize 时重设滚动位置。

## P1-A4 首轮技术补充（历史）

- 低矮遗构直接沿旋转后的顶面采样地形，以最大露出高度放置整个实体；沙丘网格负责遮挡，未裁切或隐藏模型。浏览器首轮暴露出左横梁过于完整的问题，随后改变位置、朝向和露出量，而非机械采用埋深百分比。
- 单一巨柱的前面用带孔平面与五个凹槽内面形成闭合边界。体积、拓扑及射线检查分别确认真实凹陷、朝外绕序与完整顶冠；没有叠一条深色面冒充结构切缝。凸形构件沿用既有阴影策略，凹槽巨柱接收阴影。浏览器发现旧阴影视锥裁掉新巨柱上部后，扩大固定覆盖范围，并验证巨柱顶点均位于视锥内；没有增加动态阴影跟随系统。
- 路径绕过第三块斜板，遮挡不由显隐动画驱动。离线以变换后的实际三角形采样射线，记录巨柱前面九点被遮挡及恢复的区间；这只描述该取样面域，不能当作每个像素或连续运动的证明。最终仍以浏览器原生滚动检查空间叙事。

## P1-A4 反馈修订

- 将闭合巨柱网格按高度收分，主碑与远碑共用同一实体几何；凹槽随斜面收分，仍保留真实凹陷与完整顶冠。体积积分与网格拓扑检查通过，没有改用贴片。
- 首轮碑林在主碑后方不远，浏览器中像第二排近景建筑。后移到 Z = -8800 至 -11000 后，中段以较小、较淡的轮廓出现；仅延长原高度场覆盖范围和对应网格行数，保留近谷地貌参数与网格间距。基础 Fog 的远界调整到 10000，没有引入大气系统。
- 移除中央板后，不再为了遮挡而绕行；终点后撤并抬高注视点。对露出地表的主体边界进行参考画幅投影检查，再在桌面与模拟移动视口确认完整轮廓。该检查是当前参数的有限取样，最终构图仍由浏览器画面判断。
- 最新修订将远碑放到原地形网格之外，分段向纵深排布，复用主碑几何，并按碑体所在深度设置实例颜色，让更远一段更接近天空底色。浏览器中现有沙脊仍遮住碑底，右坡遮去更多碑身。近景左段放倒后仍按旋转顶面采样控制露出，沙面保留一段朝谷道的端面。

## P1-B1 地貌与日照

- 保留谷轴、镜头关键帧、地形网格密度和巨构平面布局。将沙脊与坡脚的衔接放宽，以不同弯曲量和角度塑造横向沙丘。右侧近肩较低，中段坡脊更长，后段左岸缓坡接向主碑。只保留两级低振幅扰动。两档实际地形网格的最大相邻采样坡度均小于 0.90，镜头净空和旋转后基底的埋藏检查通过。
- 一束偏暖的低角度侧光配合偏冷的半球天空补光。主碑的受光侧面、较暗正面及切缝内壁在终点可分辨。收紧固定 PCF 阴影视锥并调节采样半径与偏移，五个近中景和主体投影网格均在视锥内。浏览器试验中地形自投影造成坡面条纹，最终由地形接收巨构投影，坡面明暗由其曲率和日照形成。
- 用普通距离雾将远处逐步混入浅冷天空，极远碑林沿用按深度递减的对比度。0%、25%、50%、75%、100% 的同进度对照保存在 `.local/p1-b1/`。在 Chromium 内嵌浏览器、AMD Radeon 的 WebGL2 环境中检查了 1280×720 桌面视口的往返滚动及 390×844 模拟手机终点。中段长投影仍有清晰边缘，谷底的大尺度色彩变化较轻。

## P1-B2 苍白硬壳与薄沙

- **地貌采样。** 在带边界余量的 25 世界单位网格采样原始高度 `H`，以 `1–2–1` 可分离核的 3×3 权重平滑成 `S`。桌面渲染网格约 25.7 单位，移动档约 48.2–50 单位，两档共用该分析网格。差分与局部平均采用半径 `r = max(37.5, 0.15w)`，其中 `w` 是对应纵深的谷地半宽，当前 `r` 为 37.5–55.5。
- **特征遮罩。** 对 `S` 做 X/Z 中心差分得到 `∇S`，坡角 `θ = atan(‖∇S‖)`，`F = 1 − smoothstep(8°, 25°, θ)`。等距取八个邻点求均值 `S̄`，用 `q = (S̄ − S)/r²` 消除半径平方的影响。`C = smoothstep(0.000045, 0.001, q)`，凸面暴露 `E` 对 `−q` 用同一范围。`V = 1 − smoothstep(0.42, 1.6, |x − x_spine(z)|/w)`。灰度调试的 `slope` 将 0°–45° 映射到 0–1。
- **覆盖与高度。** `P = clamp(0.14 + 0.38F + 0.27C + 0.18V − 0.32E + 0.07N, 0, 1)`。`N` 是固定种子 7137 驱动的两层值噪声，波长 410、205，权重 `2/3`、`1/3`。在原始分析网格内域取 `A = H₉₅ − H₅ ≈ 208.20`，`T_base = 0.025AP`，厚度上限约 5.21。最终顶点使用 `H + T_base + T_drift`，再计算法线。`sandCoverage = clamp((T_base + T_drift)/(0.025A), 0, 1)`，`exposedCrust` 为其补值。
- **局部积沙。** 仅使用左侧近景遗构和左侧中景巨板。取实际世界变换后的几何顶点，在世界风向 `(1, −0.5)`（X/Z，指向下风）下投影成凸包，横风切片的末端是背风起点。投影内与迎风侧厚度为零。若 `W` 为横风投影宽度、`d` 为离背风边缘的顺风距离，沉积从零平滑升起，随后以 `exp(−d/(1.05W))` 衰减，在 2.4–3.2 倍 `W` 间收尾。横风边缘、陡坡和受保护的谷道进一步压低沉积，每处峰值受 `min(0.032A, 0.025W)` 约束。`drift` 以该组峰值上限归一化。形态仅参考了受控障碍物后方的沉积方向，属于美术近似。仍未验证裸露截面、绕流、侵蚀和砂量守恒。[Rosset 等，2024](https://doi.org/10.1145/3651284)
- **渲染数据流。** CPU 在场景初始化时计算分析和高度，切换渲染档位时只重新采样地表网格。GPU 插值单一非颜色顶点属性 `sandCoverage`，在 `MeshStandardMaterial` 内混合冷白硬壳（`#cbd0cc`、粗糙度 0.84）和微暖细沙（`#d9cbb2`、粗糙度 0.98），颜色在线性 sRGB 混合，金属性为 0。微观方向纹理留作可选扩展，当前关闭。`?debug=1` 的六张灰度遮罩使用同一高度网格，灰度分支关闭光照、雾和色调映射，另有 `finalMaterial` 回看实际受光。[BufferAttribute](https://threejs.org/docs/pages/BufferAttribute.html) · [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html) · [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)
- **验证。** 依次在浏览器查看坡度／凹地／谷道、纯薄沙、两处背风积沙和材质混合。脚本用斜平面、凹面、凸面与旋转长方体验证符号和方向，比较独立生成的网格与遮罩，并在最终桌面和移动三角网格上复查埋藏和 1001 个相机采样。桌面最高薄沙抬升 5.19、单处额外积沙 5.60、合计最高抬升 8.02，最小地形净空 43.46 世界单位。0%、25%、50%、75%、100% 与 P1-B1 的同进度对照位于 `.local/p1-b2/`。在 1280×720 Chromium WebGL2／AMD Radeon 环境检查了往返滚动和七个调试视图，另检查了 390×844 模拟视口。滚动前后地形指纹一致，桌面稳态为 4 次绘制。Node 24 在 Ryzen 7 5800H 的五次纯 CPU 生成测量为桌面档 367–400 ms、移动网格档 201–207 ms，未包含浏览器首屏、GPU 上传和法线重算，真实手机耗时待测。

## P1-B2R 苍白风成沙漠

- **物理依据。** [USGS：Eolian Processes](https://pubs.usgs.gov/gip/deserts/eolian/) 区分沙纹、沙席和沙丘，说明沙粒通常沿缓迎风坡搬运，并从较陡的背风滑落面落下。[Nishimori 与 Ouchi，1993](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.71.197) 将沙纹与沙丘作为两个尺度的形成过程讨论；小尺度模拟显示了跃移引起的自发沙纹。[Onoue 与 Nishita，2000](https://doi.org/10.1109/PCCGA.2000.883978) 的摘要提出分尺度建模，并以带细节层级的凹凸映射表现风纹。本项目沿用两种尺度的分工，参数为视觉近似，未模拟跃移、坡面坍落、风场、颗粒或砂量守恒。
- **宏观几何。** 基础高度 `H` 和原有镜头／巨构变换保留；旧硬壳、薄沙和建筑积沙仍由 `surface.ts` 和 `pnpm check:world` 复现，正常场景不加载该层。六条沙脊分别配置中心、方位、脊长、迎风和背风宽度、高度、弯度和圆脊半径。以局部横风半长归一化得 `u`，向下风位移减去 `bend·u²` 得 `v`。左右采用各自坡宽 `W`，隆起为 `height·[(1−u²)(1−ρ(v)/ρ(W))]²`，其中 `ρ(v)=hypot(v,brink)−brink`，两端和坡脚外为零。迎风坡宽 450–940、背风坡宽 210–330 世界单位。沿谷轴 0.90–3.05 倍谷地半宽渐入，690 世界单位的低频扰动只改变最多 9% 的高度。一次性写入原网格并重算法线；对照模式的 Original terrain 是同一浅米底色下的原始高度场。
- **微观风纹。** 世界 X/Z 投影到固定下风 `(1,−0.5)` 及其横向轴，主要纹脊横风展开。连续相位叠加两条缓弯和连续的低频晶格扰动，形成缓慢疏密变化。两层名义波长为 5.9／2.55，微高度振幅为 0.115／0.042 世界单位；主纹的二次谐波略微偏斜纹形。用解析梯度扰动 Three.js 标准材质法线，逐频率以屏幕相位梯度在 0.10–0.34 周期／像素间淡出；细纹在 120–310、主纹在 275–760 世界单位间额外按视距衰减。底色统一 `#ddd0b8`，无颜色条纹；最终档仅在法线之上增加 `0.94 ± 0.035` 的缓慢粗糙度变化。
- **验证和边界。** 先单独迭代沙脊几何，再加风纹；第一版风纹过于均匀，已减弱振幅并加入局部疏密。用 Chromium WebGL2、AMD Radeon ANGLE D3D11，在 1280×720 对照四档的 0%、25%、50%、75%、100%，复查原生反向滚动，另在 390×844 模拟视口检查中段。四档同进度的相机数据一致，后三档共用网格，稳态各为 4 次绘制。脚本验证两档网格的确定性、横剖面、谷底、遗构埋藏与 1001 个镜头采样，最小地形净空 47.12 世界单位。截图位于 `.local/p1-b2r/`。风纹在顺光侧较淡，地平线保留原先的低对比度；尚未量测真机帧率或验证其他 GPU 的亚像素表现。

## P1-B2R2 沙纹纠偏与 WebGL2 基线

- **静态风纹。** 主风沿世界 X/Z 的 `(1,−0.5)`。用 77×124 世界单位的连续晶格场在相邻沙床间改变相位和覆盖，配合幅度为 4.2 的横风缓弯。相位扭曲幅度从 4.1 增到 13，让局部间距变化更明显。主纹和细纹的名义波长为 8.6／3.75，振幅为 0.062／0.015，分别比上一版下降 46%／64%。细纹轻微斜穿主纹，移除二次谐波。根据地形法线相对风向的投影，将主纹和细纹的强度偏向迎风坡，压低左侧背风坡的深纹，最陡的坡面进一步减弱。相位、覆盖和坡面权重均固定在世界坐标中。
- **抗混叠。** 在任何逐像素距离分支之前求风坐标的屏幕导数，再与各层的解析相位梯度点乘，估算每像素的周期数。两层各自在 0.09–0.30 周期／像素间淡出。细纹的距离淡出为 105–260 世界单位，主纹为 245–620，超过截止距离即跳过相位计算。材质继续用法线产生细纹的明暗。原四档地表调试用于分开对比原始地形、沙丘几何、风纹法线与最终沙材质。
- **测量方法。** 将 `5aed48b` 与修订版分别静态构建，用同一前台浏览器、同一可视区域和同一脚本交替采集，关闭开发者工具和页面调试开关。先按原生滚动范围做一次 6 秒余弦往返预热，停在 50% 并等待 1.5 秒后记录 6 秒静止。回到 0%，等待 0.8 秒，再做 6 秒同轨迹滚动，使用实际 ScrollTrigger 和相机平滑。取触发 WebGL 清屏的渲染回调计算平均帧间隔、P95 和 FPS。CPU 数值是该帧 rAF 回调在主线程的经过时间，包含 JS 和绘制提交。GPU 另测，每四帧在首次 WebGL 清屏到渲染回调结束间发出异步 `EXT_disjoint_timer_query_webgl2`，只接受结果可读且未 disjoint 的样本。静止时另记浏览器 rAF 节奏。原始 JSON、注入两份本地静态产物的测量脚本和截图保存在 `.local/p1-b2r2/`。

- **天空与远景。** 一个远平面三角形在不透明场景之后绘制。用相机射线的世界仰角在线性 sRGB 混合暖白地平线 `#e8e4d9` 与浅冷天空 `#cbd8e0`，随镜头仰俯改变取景，保持天空方向稳定。地平线、1750–12900 世界单位的 [Three.js 距离雾](https://threejs.org/docs/pages/Fog.html)、极远碑林的深度褪色共用同一个颜色端点。碑林仍由现有坡面遮住底部。
- **同机位选光。** 在 `?debug=1` 的「光照」里切换明亮柔光与雕塑感侧光，沿用同一天空、雾、曝光、几何和镜头。柔光的较高日位与更强补光让正面更均匀；侧光（太阳仰角约 20°，直射强度 3.9、半球补光 1.48）保留亮度，同时拉开丘面、碑体侧面与凹槽的明暗层次，因此设为默认。两套方案分别保留固定的 PCF 阴影视锥。

## P1-C0 近地风沙

- **风场。** 两层沿世界 X/Z 的 `(1, −0.5)` 向下风输运。种子 7137 每 6.8 秒生成一个位移扰动节点，五次插值连接相邻节点，叠加每秒 31 世界单位的基准位移。插值导数同时控制强度，两层共用这组参数。参数保证最强的反向扰动也不会令净位移倒退。世界时间来自可见期间的累计经过时间，滚动只控制相机。
- **地表。** 用一次生成的 128×128 单通道密度纹理表现疏密不等的流沙。按世界坐标采样，平滑衰减于 340–840 世界单位，以 mipmap 和显式屏幕导数过滤。密度只改变少量反射亮度，原有高度场和风纹法线保留原值。
- **低空。** 七条局部沙尘带沿浅谷分布。每条用三张高度不同、随地形弯曲的网格片近似厚度，顶点高度插值自对应档位的实际地面三角形。密度沿共享风场以地表速度的 1.68 倍输运，边缘和两端渐隐。共 3,312 个三角形合为一次透明绘制，读取现有深度，所以位置在巨构或沙丘后方的片元会被遮挡。光学模型采用固定色调的分层近似。
- **调度与对照。** 一个限频计时器向 [R3F 按需循环](https://r3f.docs.pmnd.rs/advanced/scaling-performance#on-demand-rendering) 提交渲染请求，目标桌面 60、窄屏 30 FPS。活跃时相机读取同一个绘制帧上的最新滚动信号。静态档继续由滚动请求帧，隐藏页面或减少动态效果时停止连续调度。`?debug=1` 的「风沙」可选静态、仅地表和双层。静态和仅地表使用相同绘制批次，低空沙尘增加一次绘制。

浏览器首轮在 1280×720、DPR 1 的 Chromium 157 / AMD Radeon WebGL2 上观察了地表和双层画面。地表为 5 次绘制 / 353,213 个三角形，双层为 6 次 / 356,525。采样时浏览器自身的 `requestAnimationFrame` 回调只有 1 Hz，双层静止与滚动各只取得两个有效 GPU 查询，因此剔除该轮耗时。桌面 Chrome 复测在导航检查处中止。三档同条件的帧时间、GPU 耗时和每秒持续成本仍待测，桌面与窄屏帧率目标待验证。最后一轮沙尘强度调整已通过 `pnpm check`，同机位画面对照仍待复核。首轮图像、原始样本和本地计时脚本位于 `.local/p1-c0/`。

## P1-C0R1 局部沙粒输运

- 移除移动的地表密度纹理和低空沙尘带。P1-B3 的静态材质、风纹法线、地形、光照和镜头保持原有实现。
- 十处人工设定的松沙区为每粒沙提供世界坐标起点。GPU 以场景种子、槽位和生成轮次决定生成、跃移、横向散开与淡出。每粒约 0.51–2.16 秒寿命，短沙迹回取最近 24–65 毫秒的位置。沿原有风向 `(1, −0.5)` 的位移差给出下风距离，阵风在出生时改变出粒概率、速度和寿命。双段抛物线是贴地跃移的美术近似。
- 初始化时把当前档位的实际网格高度写入单通道浮点纹理。沙迹头尾按地形原有的三角形对角线插值，深度测试让地形和巨构遮住后方沙迹。桌面最多 260 个候选槽位，窄屏 170 个。每档只用一个实例批次，沿用单一按需调度及可见期间累计的世界时间。

在 0% 机位复核 12.5 秒连续录像。近处能看到零星沙迹出现、缩短和消散，较远处更淡。固定镜头的深度探针在部分帧捕捉到被挡住的沙迹像素。往返滚动时沙迹与近景地形保持空间视差，从 50% 返回 25% 时世界时间继续增长。减少动态效果的调试开关启用后，帧计数和风时间停止。切换内嵌浏览器标签页未触发实际的页面隐藏事件，后台分支保留 `visibilitychange` 监听和 `frameloop="never"`。

## P1-C0R2 沙迹与地表清晰度

- 固定首屏机位时，旧版世界时间正常前进，约 60 FPS，CSS 尺寸与绘制缓冲都是 1280×720。对实例绘制前后各读一次缓冲，以任一颜色通道变化至少 3／255 的像素划分八邻域连通片。36 帧平均约 18 片、61 像素，每帧最宽连通片平均宽 7 像素。高对比诊断确认沙迹确实在输运。连通片只估算屏幕上的有效沙迹，重叠、遮挡和低于阈值的沙迹会影响计数。
- 近景沿原风向显示约 0.10–0.24 秒的短沙迹，中景流束由同一源点错时放出的三股细沙迹组成。各股用不同的寿命、速度和横向扩散，沿真实网格跃移并消散。近景约在 75–1020 世界单位内出现，中景约在 360–2070 内出现，距离两端淡出。新版同机位平均约 39 个可见连通片、1035 像素，每帧最宽连通片平均宽 52 像素。绿色和蓝色分别标示近景与中景，可用 `?debug=1&wind=contrast` 查看；常规画面仍用半透明沙色与深度测试。
- 旧版的近地材质单独关雾后没有像素变化，DPR 1.5 的画面降采样到同样大小后，近地平均每通道只差约 0.13／255。保留原雾及 DPR 上限。新材质增加 28×64 世界单位的定向沉积变化，以该变化打断长条沙纹，同时轻调色泽、粗糙度和法线。延长细纹、主纹的距离窗口，并分别按屏幕采样密度滤除过细条纹。较宽的沉积纹路在 480–1540 世界单位间淡出。截图与录像确认 0% 和 50% 机位的构图和地形指纹一致。

## P1-C0R3 物理引导的局部输运

- **起沙尺度。** Kok 等在式 2.5 区分流体起沙与撞击维持阈值。采用地球石英砂的流体阈值近似 `u*t = A√[((ρp−ρa)/ρa)gd]`，其中 `A=0.10`、`d=230 µm`、`ρp=2650 kg/m³`、`ρa=1.2 kg/m³`、`g=9.81 m/s²`，得 `u*t=0.223 m/s`。其表 3 的典型跃移高度和长度约 3 cm、30 cm，低于本网格尺寸。可见场表示撞击扬起的细尘柱质量，跃移阈值只用于限制其产生。未模拟单粒弹道、撞击维持或不同粒径的输运。[Kok 等，2012，第 2.1 节与表 3](https://sseh.uchicago.edu/doc/Kok_et_al_2012.pdf)
- **输运与风影依据。** Rosset 等以面通量保存沙量，按可用沙量限制输运。这里保留通量记账思想，对象是空气中的细尘与有限表层沙库，气流则由地表坡度和上风遮蔽近似。Paris 的 C++ 实现沿上风采样，默认搜索半径为 10 个仓库模型单位，其投沙过程用随机跃移与沉积。Nilles 的 CUDA 实现以最大上风坡角估计风影，并以四邻双线性权重搬运沙层。这里独立编写二维面通量和风影采样，未引入上游数值参数或复制代码，未求解三维风场、地貌演化或崩塌。[Rosset 等，2024，式 1–5](https://www-sop.inria.fr/reves/Basilic/2024/RDBC24/WindblownSand.pdf) · [Paris 等项目页](https://aparis69.github.io/public_html/projects/paris2019_Deserts.html) · [C++ 源码及 MIT 许可](https://github.com/aparis69/Desertscapes-Simulation) · [Nilles 等，第 3.4–3.5 节](https://www.scitepress.org/Papers/2024/123156/123156.pdf) · [CUDA 源码及 MIT 许可](https://github.com/Clocktown/CUDA-Dune-Simulation)
- **项目尺度与近似。** 只在首屏约 66.4×53.2 m 区域试验，约定 1 世界单位为 0.08 m。这一换算用于本实验，无真实场地量测依据。沿原主风 `(1, −0.5)`，用两个波长 27／14 m、传播速度 4／3.1 m/s 的斜向阵风调制基础摩阻速度 0.275 m/s。对渲染网格的实际三角面采样，上风 1.6–11 m 内的最高视角在 4°–23° 之间渐变为风影。遗构使用实际世界变换后的实体射线交点，地表以上超过 0.25 m 的投影格作为阻挡。坡面调整风向，风影降低摩阻速度并加快沉降。平流速度取 `11u*`，上限 5.5 m/s。四处人工设定的松沙区限制起沙位置。设 `r=u*/u*t`，起沙率为 `9 × 松沙系数 × r × max(r²−1,0)` mg/(m²·s)，同时受沙库余量约束。这里的速率、阵风、遮蔽区间与沙量是艺术实验参数。
- **数值与数据验收。** CPU 以 96×64 单元和 1/32 秒固定时间步更新双缓冲。相邻流体单元共用一阶迎风通量与 `0.15 m²/s` 中心扩散。沉降以 `0.39 s⁻¹` 的指数率把质量转回沙床，背风格最多加倍。边界允许向外平流，入流浓度及边界扩散为零。保守的流出系数和上界为 0.944，达到 1 时拒绝运行该配置。`pnpm check:world` 先独立验证低于阈值时无起沙、脉冲的下风位移、横向扩散、沉降与边界流出。首屏实际地形连续 30 秒测试中，空气浓度非负、抽样峰值为 28.85 mg/m²，沙床加空气及累计流出的总量误差小于 `1.7×10⁻⁹ mg`。守恒属于当前离散模型，视觉浓度与真实空气含尘量尚无现场校准。
- **浏览器表达。** 把浓度、风速向量和源强打包成一张 96×64 的 RGBA8 线性数据纹理。五层贴地切片取 0.095–0.82 m 高度及不同的质量权重，上层采样略偏向下风。读取场景深度用于遮挡，用视角和浓度估计光学厚度，再用日光、天空光及普通透明度混合。采用 `0.009 m²/mg` 的视觉消光系数，无自发光、加色混合或运动噪声贴图。切片有三维厚度及视差，未实现体积散射积分、尘云自阴影或对地面投影。`?debug=1` 可切静态、风场、起沙源与浓度场。滚动只控制相机，实验于进度 11.5%–19% 渐隐，离开该区域、页面隐藏或减少动态效果时停止连续绘制。

首屏以同一相机录制约 12 秒的正常画面和浓度诊断。正常画面的 2 秒及 8 秒帧中，沙尘在不同位置变浓，5 秒及 11 秒帧较淡。与静态画面逐像素比较，在画面下部任一颜色通道至少相差 `3/255` 的像素数分别为 16,824、5,988、12,026、3,660，最明显两帧的最大差值为 `9/255`。该比较说明可见变化集中在地面，不能替代对输运速度或物理浓度的校准。用原生键盘滚动往返，离开实验区域时绘制帧数和世界时间停住，回到首屏后继续前进。静态模式复核没有持续绘制，另在 390×844 桌面模拟视口检查了首屏。录像、静态对照、诊断图和原始测量留在 `.local/p1-c0r3/`。

## P1-C0R4 浅谷空间输运

- **源项。** 保留 C0R3 的起沙阈值、阵风、平流、扩散和沉降。松沙可用度改为连续地貌场，沿世界 Z 平滑插值宽尺度沙量，再由谷轴距离、55 世界单位邻域的坡度与局部凹凸修正。沿风、横风尺度 205／105 世界单位的确定性低频场形成疏密不同的沙层。原有摩阻速度随阵风、坡面和上风遮蔽变化，仅在超过 0.223 m/s 时消耗可用沙。风影采样扩到参与浅谷的遗构和中景巨板，使用实际实体的世界变换。中段有更多可输运松沙，抵达主碑前的世界区域沙量逐渐收低。
- **活动窗。** 连续世界格覆盖约 100×558 m，共 112×656 格。每步只更新覆盖当前取景的 112×172 格（约 100×146 m）。窗口从相机前方约 1510 世界单位开始，每 4 个完整世界网格行移位。浓度与沙床状态留在原世界格，重叠区域不重新采样。首次进入的格点从当地沙床拨出少量浓度，以 3.2 m 上风处约 1.1 秒前的起沙率估算。离开窗口的格点保留存量，重新进入时把离开期间的沉降量归还沙床。长距离跳转仍沿用同一个阵风时钟。
- **边界与显示。** 纵向窗口边缘使用上述上风估算提供平流入流，流出和流入分别计入质量账，外边界没有扩散通量。水平视距 760–1240 世界单位内渐隐，使纵向边界落在可见半径之外。贴地切片复用原地形三角面和法线，一次绘制只取相机附近的网格行，采样位置以世界坐标计算。窗口挪动不移动网格或沙尘纹理。未活动区域仅近似沉降，未同时求解全谷的平流。相同窗口轨迹、固定时间步和种子可复现。

- J3-B 薄云研究。r187 示例把云投影到方向空间，以覆盖度、光学厚度和同一散射光照衔接天空。若基础天空通过评审，可先试静态、低覆盖的薄云，优先评估低仰角渐隐和主碑轮廓的对比度。

## P1-J3R 天空与巨构光照对照

- 原版天空向前抬高 20° 的同一条视线，原始散射在线性 RGB 约为 `(0.161, 0.505, 1.158)`，曝光 1.36、逐通道压缩、饱和度 0.46 与黑白点 0.515/0.952 处理后为 `(0.639, 0.685, 0.726)`。暗部抬升和高光压缩同时收窄了光色差异。新三案沿用天空曝光 1.36，在线性散射中保留少量色度，再以统一通道增益压缩高光并降低黑点。半精度 LUT 存显示参考的线性 sRGB，表面以 ACES（曝光 1.03）映射后与 LUT 混合，最后一次性转为 sRGB。天空本身直接使用同一 LUT。[Three.js r187 Sky.js](https://github.com/mrdoob/three.js/blob/r187/examples/jsm/objects/Sky.js) · [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)
- **A 雕塑式侧光。** 右侧日照与较低的天空补光分出沙丘脊线和碑体明暗面，Arrival 纵槽最深，前景投影也最明显。
- **B 薄霾逆光。** 偏右的斜逆光、较强 Mie 散射与较近的距离雾拉开碑体和天空的轮廓。首轮正逆光压没了纵槽，改为斜逆光后 Arrival 的纵槽重新可读，反差仍比 A 低。
- **C 柔和日照与分层空气。** 较高的太阳角度减弱投影，沿视线在 1050–5400 世界单位间平滑加入最多 14% 的近层空气光，再衔接远雾与极远碑林的衰减。此案的碑面明暗反差更轻。
- 三案的日照、LUT 太阳方向与固定阴影共用同一太阳向量。各阴影视锥通过既有构件和落地投影范围检查。调试页的「光照」选单保留四案，正式画面仍使用原版。Chromium WebGL2 的 1600×1000、DPR 1 下，Opening / Passage / Arrival 的相机姿态与地形一致，切回原版后与 J3 本地截图逐像素相同。关闭风沙的 12 次固定机位停留各观察约 430 ms，均无额外渲染帧。对照截图、LUT 采样和浏览器原始数据留在 `.local/p1-j3r/`。

## P1-J3D 天空材质分层

- 保留原有 Preetham 色表与日照。大尺度色场用两层低频噪声微调线性颜色。高空云纱用拉长、缓弯的噪声叠加密度包络，沿仰角渐隐。两个遮罩由种子生成，合存于 256×128 的双通道方向纹理（64 KiB），按世界视线取样。
- 色场与云纱在地平线收弱。天穹和场景空气透视共用一层暖薄霾，远碑沿用距离衰减并轻微向雾色靠拢。天空输出转为 sRGB 后叠加静态中性抖动，幅度为半个 8 位色阶。
- `?debug=1` 的「天空分层」可单独切换四层，或在纯解析天空和全层之间对照。Chromium 157 WebGL2、AMD Radeon 集显、1600×1000、DPR 1 下检查了 0%、35%、100% 三机位的六种画面。逐层像素对照确认四个开关均生效，微纹理最多改变一个 8 位色阶。关闭风沙时三处稳态均为 5 次绘制，停留 650 ms 均无新增帧。截图与采样保存在 `.local/p1-j3d/`。

## P1-J3D-R2 定向云纱

- 以世界方向布置三条云带：Opening 左侧斜向长带、右侧较短的平缓云带，以及 Arrival 仰望时显露的高层淡云。每条由方位角、仰角、长宽、切平面内方向及覆盖强度控制。以软椭圆限制云域，域内用沿带方向拉长的三层噪声、低频弯折、次级偏移与连续断裂遮罩形成疏密不同的云丝。[WMO 卷云](https://cloudatlas.wmo.int/definition-cirrus-ci.html)与[卷层云](https://cloudatlas.wmo.int/en/definition-cirrostratus-cs.html)仅作为形态参考。
- 用 `τ = 0.56 × 云域包络 × 纤维遮罩`、`T = exp(−τ)` 混合透射天光与云纱光色。这是光学厚度的美术近似，未模拟体积散射。低仰角色场比上一版更早显现，云纱仅被最终暖薄霾轻轻压低，不再被同一渐隐重复削弱。
- 保留原有 Preetham 解析项。CPU 将解析色、色场、云纱与地平线薄霾合成一张 512×256 RGBA16F 方向色表（1 MiB）；水平方位循环采样，垂直采样在地平线加密。天空、地表和碑林的空气透视共用同一线性 sRGB 颜色，表面色经 ACES 后与它混合，之后统一转为 sRGB。云丝噪声只在初始化生成；调试切换材质层时重合成色表。静态抖动保留在天空的输出端。
- `?debug=1` 的「天空视图」切换最终光色、云域包络、纤维遮罩及归一化光学厚度 `τ / 0.56`。调试遮罩使用独立的 RGBA8 纹理，仅在调试模式上传；它只替换天幕画面，以保留原地形和巨构作为构图参照。

浏览器在 Opening / Passage / Arrival（滚动 0% / 35% / 100%）检查最终画面和三类遮罩：首屏能读出两侧走向不同的云纱，中景碑体与天穹的远雾过渡连续，终点高层云丝不遮挡主碑轮廓。两版相机位置、朝向、FOV 与地形指纹一致。关掉风沙时每帧 5 次绘制，三个机位各停留 650 ms 均无额外帧。另检查 Chromium 390×844 窄视口的首屏和终点调试切换；未测真实手机性能。原始截图、遮罩及计时数据留在 `.local/p1-j3d-r2/`。

| --- | ---: | ---: |

| Passage | 3.74–3.87 / 4.20–4.76 | 3.90–3.96 / 4.47–4.59 |
| Arrival | 2.82–3.00 / 3.28–3.49 | 2.81–2.84 / 3.38–3.51 |

两版均为稳态 6 次绘制、约 60 FPS。R2 两轮均值增幅最大的是 Opening，约 0.19 ms。两次独立页面初始化中，解析色表及重投影为 11.9–12.8 ms，云域和纤维遮罩为 21.9–26.9 ms，最终色表合成为 7.0–8.0 ms，CPU 合计约 42–47 ms；不含纹理上传、着色器编译和页面加载。未测不同 GPU 或高 DPR 的性能。

## P1-J3E 连续天空场

- 将世界方向转换到倾斜的球面流向坐标：沿流向用周期经度，横向用到参考大圆的有符号角距。主云纱以连续曲线控制位置、宽度与密度；两条较淡的支带沿同一骨架偏移，逐渐分开或汇入。沿流向拉长的纤维经过共享的轻微坐标弯折和分叉，始终限制在云带内部。流向经度在两端交叠取样，云带避开该坐标系的两极；底场直接取世界方向的笛卡尔分量，高仰角也不依赖经度。
- 底场由低频明度、冷暖偏移和微弱薄霾组成。保留 Preetham、太阳与距离衰减参数，并以 `T = exp(−τ)` 合成云光。初始化在 CPU 生成场，天空和空气透视仍共用同一张 512×256 线性 RGBA16F 方向色表。窗口变化不重新生成色表。`?debug=1` 只保留底场、主云带、次云带、最终合成四项天空视图，各项都使用同一色表和空气透视路径。

在 Chromium 的 1600×1000、1920×800、390×844 和 1000×1250 视口检查 Opening / Passage / Arrival。三处均保留横贯视野的主云纱，窄屏没有切回孤立云块。Passage 在同一页面从 1600×1000 缩放到 890×1130 时，旅程进度保持 0.356，色表未重算。三个桌面机位经鼠标偏转回正后，画布与原帧逐像素一致；关闭风沙时，12 个固定画面各停留 650 ms 均无新增帧。独立生成的遮罩字节一致，世界方位接缝相邻两列的通道变化未超过普通相邻列，天顶各方位样本一致。截图和原始数据留在 `.local/p1-j3e/`。

沿用 R2 的 Chromium 157 / WebGL2、AMD Radeon 集显（ANGLE D3D11）、1600×1000、DPR 1 与开启风沙的固定机位测试。每版两轮，每机位停稳后采 3 秒；每轮有 45–46 个有效 GPU 样本，无 disjoint 或后台采样。GPU 平均 / P95 耗时范围（ms）：

| Opening | 3.72–3.99 / 4.18–4.60 | 3.64–3.72 / 4.19–4.32 |
| Passage | 3.70–3.95 / 4.39–4.68 | 3.57–3.68 / 4.17–4.26 |
| Arrival | 2.83–2.99 / 3.27–3.47 | 2.65–2.66 / 3.14–3.24 |

两版均为稳态 6 次绘制、约 60 FPS。此对照的单次 CPU 初始化（解析、生成场、合成，不含上传和着色器编译）从 52.2 ms 增至 69.5 ms；J3E 的场生成占 49.1 ms。未测真实手机、高 DPR 或其他 GPU。

## P1-E1 静默圣域

- 以主碑的世界位置、尺寸和基部沙面定义椭球场，半轴约为 2438 × 1815 × 2520 世界单位。归一化坐标 `q` 上的影响值为 `max(0, 1 - dot(q, q))²`，光晕和光粒共用该范围及衰减；`sanctuaryInfluence` 可供之后的风沙系统取样，本轮未接入。
- 暖金散射沿视线解析积分，遇到不透明表面即结束；只有天空方向使用完整路径。它叠加在现有天空、距离雾与碑面受光之后，无额外体积绘制。初版视线切片曾在碑面留下可见的分层轮廓，已移除。当前是定色散射近似，不模拟阴影里的多次散射。
- 近地和高空光粒以现有地形三角面为发射基准，分别以 4.5–8.5 秒和 9–16 秒错相循环。一批 GPU 点绘制两层，使用原场景的深度缓冲与渲染调度。鼠标以世界射线和有限纵深计算扰动，反馈后最大强度从 67 调到 25 世界单位；镜头输入和风沙保留原有逻辑。减少动态效果时固定光粒构图，隐藏时暂停计时。
- Chrome 157 / WebGL2、AMD Radeon 集显（ANGLE D3D11），1560×900、DPR 1、终点固定镜头、保留现有风沙，`?debug=1&sanctuary=off` 对照开启状态。预热后各采两轮，每轮 3.9 秒、234 个有效 GPU 样本。GPU 平均 / P95：关闭 2.35–2.52 / 2.89–3.17 ms，开启 2.46–2.47 / 2.97–2.99 ms；均约 60 FPS，绘制 6 → 7 次，三角面数不变。另检查了 520×900 窄窗口及减少动态效果；未测真机。对照截图和原始数据留在 `.local/p1-e1/`。
