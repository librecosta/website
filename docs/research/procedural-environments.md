# 程序化环境研究 · P1-A

2026-11-06。目标是先确认荒原的空间灰模；以下是技术取舍，不冻结世界观、建筑母题或最终镜头。没有引入 Houdini 运行时，也未下载第三方设计资产。

## 研究与取舍

| 主题 | 技术思想与优缺点 | LibreCosta 的采用方式 |
| --- | --- | --- |
| 人工 Massing | 先控制山体占地、高低关系与围合空间，再增加细节，比全域叠噪声更容易保持构图；需要明确的人工空间决策。 | P1-A3 修订以中轴、横截面和 3 条连续坡脊建立相接沙体，左岸叠加 2 处重叠的横风丘面。局部丘面服从连续基底，不沿纵深复制孤立丘包。 |
| Heightfield 与多尺度噪声 | 二维网格保存高度，便于分层与重采样；不能表示悬挑、洞穴和同一平面坐标上的多层地表。细节尺度过小而振幅过大容易产生尖峰。 | CPU 上生成确定性高度，转换为真实索引网格并重算顶点法线。大尺度形体优先，三层低振幅平滑值噪声只补自然变化，不做侵蚀模拟。 |
| 局部生成遮罩 | 遮罩限制某层效果的作用范围，便于分开调整道路、盆地和山脊；遮罩过硬会产生突兀台地。 | 通道随谷地弯曲，保留 12% 丘脊起伏，横向渐变加宽至 440 单位以避免丘面相接后出现过陡内坡。实体仍按旋转后脚底采样并下沉，不靠换色埋藏。 |
| 程序化与模块化 | 先定义构件与空间规则，再重复组合；可迭代、可复现，缺点是容易显得等距机械或像随机城市。 | P1-A4 反馈后保留外倾双板：`ideal` 记录基准，`disturbed` 记录手工偏移、沉降与倾斜。近处左段横卧、右段内倾，远处碑林与主碑采用同一种收分几何。 |
| InstancedMesh | 同几何、同材质的不同变换可合并提交；不能自动解决材质多样性、实例级剔除或过大批次包围范围的问题。 | 当前 4 个长方体共享一批，5 座远碑与主碑共享一批凹槽台体，共用灰材质。不创建空实例批次，不建立空间分块平台。 |
| 空气、光与几何 | 雾降低远处对比，日光显露体量；过浓的雾或过强环境光会掩盖构图缺陷。 | 用基础 DirectionalLight、HemisphereLight、阴影与线性 Fog；近处保持清楚，远方融入同色天空。不加 Bloom、粒子或体积云。 |
| 离线／实时边界 | 离线适合独特结构和复杂静态细节，实时适合参数布局与响应视口；烘焙材质不等于可直接迁移整套离线光照。 | 本轮全部是基础几何和灰模材质；Blender 留待重要独特资产与必要烘焙，整体构图通过前不做高模与精细纹理。 |

地形的分层、遮罩与限制来自 [SideFX Heightfields](https://www.sidefx.com/docs/houdini/heightfields/)，先 Massing 后细节与逐步重采样的思路来自 [Terrain Creation](https://www.sidefx.com/docs/houdini/heightfields/creation.html)。我们采用其制作逻辑，不复制 Houdini 的噪声或侵蚀实现。

实例化的 API、矩阵更新与包围体职责以 [Three.js InstancedMesh 文档](https://threejs.org/docs/pages/InstancedMesh.html) 为准。Crosswire 文章讨论的是 2023 年的实现限制，不能据此断言当前 Three.js 完全不支持实例网格包围体剔除。

## 当前实现与待验证事项

- 参数源：`src/components/expanse/parameters.ts`；地形、埋藏与路径算法：同目录 `world.ts`。固定种子只控制地貌细节，所有巨构布局人工配置。
- 只有 `/lab/expanse` 初始化一个客户端 Canvas，正式首页维持原状；品牌、无障碍标题与空间描述独立于 WebGL。正常画面没有观察点、研究说明或额外导航；没有外部模型、纹理或天空资产请求。
- 移动端使用较低地形网格密度和 DPR 上限。相机共用同一路径，以 2:1 参考画幅做 contain 取景：窄窗保留水平范围，整体缩小并增加上下视野。竖屏主体占比下降是明确取舍，不靠固定的移动端 FOV 增量裁切构图。桌面模拟移动视口不等于真实手机性能或触摸手势验证。
- **待验证／后续范围**：真实手机 GPU、触控板／触摸硬件和功耗；更复杂地形下的分块与 LOD；最终高速镜头；需要更复杂大气时的成本。本轮仅验证现有受控路径。

本轮浏览器观察与仍存构图问题记录于 [expanse-blockout.md](expanse-blockout.md)。后续按 **地形 → 巨构布局 → 镜头构图 → 空气与光线 → 正式材质** 迭代。

## P1-A3 首轮观察（历史）

- 原有单层 Massing 的起伏不足以建立谷中视角。将中轴、谷底高程、横截面、分层丘脊和局部覆沙拆开后，浏览器能读出左右包裹与逐层遮挡；仅增加噪声振幅没有用于解决此问题。
- 近丘过高会吞掉中景，低矮残片靠近镜头后也会显得像完整方块。本轮降低右侧近丘、拓宽通道渐变，并将残片露出高度压到约 23–37 单位，保留主体远近层级。这些是当前视角观察，不是适用于所有布局的最优参数。
- 相机位置相对同一谷地中轴采样，眼高相对真实地形高度。桌面与移动网格分别做轨迹净空检查，避免降采样后通道局部抬高而穿地；前 20% 的位置、注视点、视角和滚转保持不变。
- 用路由内 DOM 的 `:has()` 选择器隐藏根滚动条外观，保留原生文档高度；底部细线读取原生进度，GSAP 的短暂追随只影响相机进度。没有拦截 wheel 或用进度条接管输入。

## P1-A3 反馈后的修订

- 首轮独立椭圆丘脊仍产生重复的凹口，不能把“一个高度网格”误认为视觉上已经连贯。当前坡脊沿纵深连续插值，彼此平滑融合；两处交叠丘面在连续沙体上塑形，保留层次，避免每个丘包单独降到谷底。
- 左侧两条坡脊间用两种实际地形网格采样连接带；最低连接高差约 97.96 单位，高于谷底。此数值是当前布局的有限采样结果，不是对任意参数的连续性证明，也不能替代画面评审。
- 前 20% 静止段会让用户误以为没有响应。已取消，起点前移，首端使用非零位移导数，短暂进度追随改为 0.18 秒；有效滚动长度为首次视窗高度的 3 倍。
- 固定垂直 FOV 会在窄窗裁去两侧。按参考画幅计算垂直 FOV 后，468 次可见建筑顶点对照均保留了原水平投影与画幅内位置；仍需浏览器检查取景，不能把这个投影检查当作艺术验收。
- 仅修正 FOV 还不够：若文档始终以实时 vh 计算总长度，改变窗口高度会改变同一 scrollTop 的旅程进度。当前将本次访问的原生滚动距离固定为像素，只让粘性画布跟随实时视窗高度；无需在 resize 时重设滚动位置。

## P1-A4 首轮技术补充（历史）

- 低矮遗构直接沿旋转后的顶面采样地形，以最大露出高度放置整个实体；沙丘网格负责遮挡，未裁切或隐藏模型。浏览器首轮暴露出左横梁过于完整的问题，随后改变位置、朝向和露出量，而非机械采用埋深百分比。
- 单一巨柱的前面用带孔平面与五个凹槽内面形成闭合边界。体积、拓扑及射线检查分别确认真实凹陷、朝外绕序与完整顶冠；没有叠一条深色面冒充结构切缝。凸形构件沿用既有阴影策略，凹槽巨柱接收阴影。浏览器发现旧阴影视锥裁掉新巨柱上部后，扩大固定覆盖范围，并验证巨柱顶点均位于视锥内；没有增加动态阴影跟随系统。
- 路径绕过第三块斜板，遮挡不由显隐动画驱动。离线以变换后的实际三角形采样射线，记录巨柱前面九点被遮挡及恢复的区间；这只描述该取样面域，不能当作每个像素或连续运动的证明。最终仍以浏览器原生滚动检查空间叙事。

## P1-A4 反馈修订

- 将闭合巨柱网格按高度收分，主碑与远碑共用同一实体几何；凹槽随斜面收分，仍保留真实凹陷与完整顶冠。体积积分与网格拓扑检查通过，没有改用贴片。
- 首轮碑林在主碑后方不远，浏览器中像第二排近景建筑。后移到 Z = -8800 至 -11000 后，中段以较小、较淡的轮廓出现；仅延长原高度场覆盖范围和对应网格行数，保留近谷地貌参数与网格间距。基础 Fog 的远界调整到 10000，没有引入大气系统。
- 移除中央板后，不再为了遮挡而绕行；终点后撤并抬高注视点。对露出地表的主体边界进行参考画幅投影检查，再在桌面与模拟移动视口确认完整轮廓。该检查是当前参数的有限取样，最终构图仍由浏览器画面判断。
- 最新修订将远碑放到原地形网格之外，分段向纵深排布，复用主碑几何，并按碑体所在深度设置实例颜色，让更远一段更接近天空底色。浏览器中现有沙脊仍遮住碑底，右坡遮去更多碑身。近景左段放倒后仍按旋转顶面采样控制露出，沙面保留一段朝谷道的端面。

## P1-B1 地貌与日照

- 保留谷轴、镜头关键帧、地形网格密度和巨构平面布局。将沙脊与坡脚的衔接放宽，以不同弯曲量和角度塑造横向沙丘。右侧近肩较低，中段坡脊更长，后段左岸缓坡接向主碑。只保留两级低振幅扰动。两档实际地形网格的最大相邻采样坡度均小于 0.90，镜头净空和旋转后基底的埋藏检查通过。
- 一束偏暖的低角度侧光配合偏冷的半球天空补光。主碑的受光侧面、较暗正面及切缝内壁在终点可分辨。收紧固定 PCF 阴影视锥并调节采样半径与偏移，五个近中景和主体投影网格均在视锥内。浏览器试验中地形自投影造成坡面条纹，最终由地形接收巨构投影，坡面明暗由其曲率和日照形成。
- 用普通距离雾将远处逐步混入浅冷天空，极远碑林沿用按深度递减的对比度。0%、25%、50%、75%、100% 的同进度对照保存在 `.local/p1-b1/`。在 Chromium 内嵌浏览器、AMD Radeon 的 WebGL2 环境中检查了 1280×720 桌面视口的往返滚动及 390×844 模拟手机终点。中段长投影仍有清晰边缘，谷底的大尺度色彩变化较轻。

## P1-B2 苍白硬壳与薄沙

- **地貌采样。** 在带边界余量的 25 世界单位网格采样原始高度 `H`，以 `1–2–1` 可分离核的 3×3 权重平滑成 `S`。桌面渲染网格约 25.7 单位，移动档约 48.2–50 单位，两档共用该分析网格。差分与局部平均采用半径 `r = max(37.5, 0.15w)`，其中 `w` 是对应纵深的谷地半宽，当前 `r` 为 37.5–55.5。
- **特征遮罩。** 对 `S` 做 X/Z 中心差分得到 `∇S`，坡角 `θ = atan(‖∇S‖)`，`F = 1 − smoothstep(8°, 25°, θ)`。等距取八个邻点求均值 `S̄`，用 `q = (S̄ − S)/r²` 消除半径平方的影响。`C = smoothstep(0.000045, 0.001, q)`，凸面暴露 `E` 对 `−q` 用同一范围。`V = 1 − smoothstep(0.42, 1.6, |x − x_spine(z)|/w)`。灰度调试的 `slope` 将 0°–45° 映射到 0–1。
- **覆盖与高度。** `P = clamp(0.14 + 0.38F + 0.27C + 0.18V − 0.32E + 0.07N, 0, 1)`。`N` 是固定种子 7137 驱动的两层值噪声，波长 410、205，权重 `2/3`、`1/3`。在原始分析网格内域取 `A = H₉₅ − H₅ ≈ 208.20`，`T_base = 0.025AP`，厚度上限约 5.21。最终顶点使用 `H + T_base + T_drift`，再计算法线。`sandCoverage = clamp((T_base + T_drift)/(0.025A), 0, 1)`，`exposedCrust` 为其补值。
- **局部积沙。** 仅使用左侧近景遗构和左侧中景巨板。取实际世界变换后的几何顶点，在世界风向 `(1, −0.5)`（X/Z，指向下风）下投影成凸包，横风切片的末端是背风起点。投影内与迎风侧厚度为零。若 `W` 为横风投影宽度、`d` 为离背风边缘的顺风距离，沉积从零平滑升起，随后以 `exp(−d/(1.05W))` 衰减，在 2.4–3.2 倍 `W` 间收尾。横风边缘、陡坡和受保护的谷道进一步压低沉积，每处峰值受 `min(0.032A, 0.025W)` 约束。`drift` 以该组峰值上限归一化。形态仅参考了受控障碍物后方的沉积方向，属于美术近似。仍未验证裸露截面、绕流、侵蚀和砂量守恒。[Rosset 等，2024](https://doi.org/10.1145/3651284)
- **渲染数据流。** CPU 在场景初始化时计算分析和高度，切换渲染档位时只重新采样地表网格。GPU 插值单一非颜色顶点属性 `sandCoverage`，在 `MeshStandardMaterial` 内混合冷白硬壳（`#cbd0cc`、粗糙度 0.84）和微暖细沙（`#d9cbb2`、粗糙度 0.98），颜色在线性 sRGB 混合，金属性为 0。微观方向纹理留作可选扩展，当前关闭。`?debug=1` 的六张灰度遮罩使用同一高度网格，灰度分支关闭光照、雾和色调映射，另有 `finalMaterial` 回看实际受光。[BufferAttribute](https://threejs.org/docs/pages/BufferAttribute.html) · [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html) · [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)
- **验证。** 依次在浏览器查看坡度／凹地／谷道、纯薄沙、两处背风积沙和材质混合。脚本用斜平面、凹面、凸面与旋转长方体验证符号和方向，比较独立生成的网格与遮罩，并在最终桌面和移动三角网格上复查埋藏和 1001 个相机采样。桌面最高薄沙抬升 5.19、单处额外积沙 5.60、合计最高抬升 8.02，最小地形净空 43.46 世界单位。0%、25%、50%、75%、100% 与 P1-B1 的同进度对照位于 `.local/p1-b2/`。在 1280×720 Chromium WebGL2／AMD Radeon 环境检查了往返滚动和七个调试视图，另检查了 390×844 模拟视口。滚动前后地形指纹一致，桌面稳态为 4 次绘制。Node 24 在 Ryzen 7 5800H 的五次纯 CPU 生成测量为桌面档 367–400 ms、移动网格档 201–207 ms，未包含浏览器首屏、GPU 上传和法线重算，真实手机耗时待测。

## P1-B2R 苍白风成沙漠

- **物理依据。** [USGS：Eolian Processes](https://pubs.usgs.gov/gip/deserts/eolian/) 区分沙纹、沙席和沙丘，说明沙粒通常沿缓迎风坡搬运，并从较陡的背风滑落面落下。[Nishimori 与 Ouchi，1993](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.71.197) 将沙纹与沙丘作为两个尺度的形成过程讨论；小尺度模拟显示了跃移引起的自发沙纹。[Onoue 与 Nishita，2000](https://doi.org/10.1109/PCCGA.2000.883978) 的摘要提出分尺度建模，并以带细节层级的凹凸映射表现风纹。本项目沿用两种尺度的分工，参数为视觉近似，未模拟跃移、坡面坍落、风场、颗粒或砂量守恒。
- **宏观几何。** 基础高度 `H` 和原有镜头／巨构变换保留；旧硬壳、薄沙和建筑积沙仍由 `surface.ts` 和 `pnpm check:world` 复现，正常场景不加载该层。六条沙脊分别配置中心、方位、脊长、迎风和背风宽度、高度、弯度和圆脊半径。以局部横风半长归一化得 `u`，向下风位移减去 `bend·u²` 得 `v`。左右采用各自坡宽 `W`，隆起为 `height·[(1−u²)(1−ρ(v)/ρ(W))]²`，其中 `ρ(v)=hypot(v,brink)−brink`，两端和坡脚外为零。迎风坡宽 450–940、背风坡宽 210–330 世界单位。沿谷轴 0.90–3.05 倍谷地半宽渐入，690 世界单位的低频扰动只改变最多 9% 的高度。一次性写入原网格并重算法线；对照模式的 Original terrain 是同一浅米底色下的原始高度场。
- **微观风纹。** 世界 X/Z 投影到固定下风 `(1,−0.5)` 及其横向轴，主要纹脊横风展开。连续相位叠加两条缓弯和连续的低频晶格扰动，形成缓慢疏密变化。两层名义波长为 5.9／2.55，微高度振幅为 0.115／0.042 世界单位；主纹的二次谐波略微偏斜纹形。用解析梯度扰动 Three.js 标准材质法线，逐频率以屏幕相位梯度在 0.10–0.34 周期／像素间淡出；细纹在 120–310、主纹在 275–760 世界单位间额外按视距衰减。底色统一 `#ddd0b8`，无颜色条纹；最终档仅在法线之上增加 `0.94 ± 0.035` 的缓慢粗糙度变化。
- **验证和边界。** 先单独迭代沙脊几何，再加风纹；第一版风纹过于均匀，已减弱振幅并加入局部疏密。用 Chromium WebGL2、AMD Radeon ANGLE D3D11，在 1280×720 对照四档的 0%、25%、50%、75%、100%，复查原生反向滚动，另在 390×844 模拟视口检查中段。四档同进度的相机数据一致，后三档共用网格，稳态各为 4 次绘制。脚本验证两档网格的确定性、横剖面、谷底、遗构埋藏与 1001 个镜头采样，最小地形净空 47.12 世界单位。截图位于 `.local/p1-b2r/`。风纹在顺光侧较淡，地平线保留原先的低对比度；尚未量测真机帧率或验证其他 GPU 的亚像素表现。
