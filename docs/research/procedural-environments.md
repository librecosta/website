# 程序化环境研究 · P1-A

2026-11-06。目标是先确认荒原的空间灰模；以下是技术取舍，不冻结世界观、建筑母题或最终镜头。没有引入 Houdini 运行时，也未下载第三方设计资产。

## 研究与取舍

| 主题 | 技术思想与优缺点 | LibreCosta 的采用方式 |
| --- | --- | --- |
| 人工 Massing | 先控制山体占地、高低关系与围合空间，再增加细节，比全域叠噪声更容易保持构图；需要明确的人工空间决策。 | P1-A3 修订以中轴、横截面和 3 条连续坡脊建立相接沙体，左岸叠加 2 处重叠的横风丘面。局部丘面服从连续基底，不沿纵深复制孤立丘包。 |
| Heightfield 与多尺度噪声 | 二维网格保存高度，便于分层与重采样；不能表示悬挑、洞穴和同一平面坐标上的多层地表。细节尺度过小而振幅过大容易产生尖峰。 | CPU 上生成确定性高度，转换为真实索引网格并重算顶点法线。大尺度形体优先，三层低振幅平滑值噪声只补自然变化，不做侵蚀模拟。 |
| 局部生成遮罩 | 遮罩限制某层效果的作用范围，便于分开调整道路、盆地和山脊；遮罩过硬会产生突兀台地。 | 通道随谷地弯曲，保留 12% 丘脊起伏，横向渐变加宽至 440 单位以避免丘面相接后出现过陡内坡。实体仍按旋转后脚底采样并下沉，不靠换色埋藏。 |
| 程序化与模块化 | 先定义构件与空间规则，再重复组合；可迭代、可复现，缺点是容易显得等距机械或像随机城市。 | P1-A4 以三块巨板表达失序列阵：`ideal` 记录基准，`disturbed` 记录手工偏移、沉降与倾斜。近处两组微露遗构、远处一个静默巨柱，种子只影响地形细节。 |
| InstancedMesh | 同几何、同材质的不同变换可合并提交；不能自动解决材质多样性、实例级剔除或过大批次包围范围的问题。 | 当前 6 个长方体共享一批，凹槽巨柱为另一个闭合网格，共用灰材质。没有台形时不创建空批次；不建立空间分块平台。 |
| 空气、光与几何 | 雾降低远处对比，日光显露体量；过浓的雾或过强环境光会掩盖构图缺陷。 | 用基础 DirectionalLight、HemisphereLight、阴影与线性 Fog；近处保持清楚，远方融入同色天空。不加 Bloom、粒子或体积云。 |
| 离线／实时边界 | 离线适合独特结构和复杂静态细节，实时适合参数布局与响应视口；烘焙材质不等于可直接迁移整套离线光照。 | 本轮全部是基础几何和灰模材质；Blender 留待重要独特资产与必要烘焙，整体构图通过前不做高模与精细纹理。 |

地形的分层、遮罩与限制来自 [SideFX Heightfields](https://www.sidefx.com/docs/houdini/heightfields/)，先 Massing 后细节与逐步重采样的思路来自 [Terrain Creation](https://www.sidefx.com/docs/houdini/heightfields/creation.html)。我们采用其制作逻辑，不复制 Houdini 的噪声或侵蚀实现。

实例化的 API、矩阵更新与包围体职责以 [Three.js InstancedMesh 文档](https://threejs.org/docs/pages/InstancedMesh.html) 为准。Crosswire 文章讨论的是 2023 年的实现限制，不能据此断言当前 Three.js 完全不支持实例网格包围体剔除。

## 案例参考

- [Three.js Terrain + Fog](https://threejs.org/examples/webgl_geometry_terrain.html) 及其 [r187 源码](https://github.com/mrdoob/three.js/blob/r187/examples/webgl_geometry_terrain.html)：展示高度生成、地形几何与雾组合的基础路径。本项目只借鉴职责划分，不复用其纹理生成或自由移动操作。
- [Unseen Studio：Crosswire](https://tympanus.net/codrops/2023/04/04/case-study-crosswire/)：作者将品牌构件组织为三维网格，离线导出布局信息，再实例化重复模型；为匹配画面，曾以多张 Matcap 替代昂贵反射。本项目借鉴“布局数据与重复构件分离”，不采用其金属美术、扫描波和拖尾。文章直连曾返回 403，正文通过检索索引读取。
- [Animorio：Hubtown 逆向参考](https://animorio.com/en/journal/hubtown-how-its-made/)：属于第三方逆向分析，不是原作者制作说明。文中声称地形来自 Houdini 高度图，并结合压缩纹理、glTF 与镜头编排。**这些实现细节未独立核实**；仅作为未来离线高度场与实时布局分工的研究线索，不照搬蓝色夜景、发光体、水面、加载仪式或滚动系统。
- [R3F Scaling Performance](https://r3f.docs.pmnd.rs/advanced/scaling-performance)：采用按需渲染。P1-A2 由 GSAP ScrollTrigger 更新进度并请求渲染，`useFrame` 是唯一相机写入者；空闲后停止请求帧，页面隐藏时暂停渲染。没有两套系统同时平滑相机属性。

## 当前实现与待验证事项

- 参数源：`src/components/expanse/parameters.ts`；地形、埋藏与路径算法：同目录 `world.ts`。固定种子只控制地貌细节，所有巨构布局人工配置。
- 只有 `/lab/expanse` 初始化一个客户端 Canvas，正式首页维持原状；品牌、无障碍标题与空间描述独立于 WebGL。正常画面没有观察点、研究说明或额外导航；没有外部模型、纹理或天空资产请求。
- 移动端使用较低地形网格密度和 DPR 上限。相机共用同一路径，以 2:1 参考画幅做 contain 取景：窄窗保留水平范围，整体缩小并增加上下视野。竖屏主体占比下降是明确取舍，不靠固定的移动端 FOV 增量裁切构图。桌面模拟移动视口不等于真实手机性能或触摸手势验证。
- **待验证／后续范围**：真实手机 GPU、触控板／触摸硬件和功耗；更复杂地形下的分块与 LOD；最终高速镜头；需要更复杂大气时的成本。本轮仅验证现有受控路径。

本轮浏览器观察与仍存构图问题记录于 [expanse-blockout.md](expanse-blockout.md)。后续按 **地形 → 巨构布局 → 镜头构图 → 空气与光线 → 正式材质** 迭代。

## P1-A3 首轮观察（历史）

- 原有单层 Massing 的起伏不足以建立谷中视角。将中轴、谷底高程、横截面、分层丘脊和局部覆沙拆开后，浏览器能读出左右包裹与逐层遮挡；仅增加噪声振幅没有用于解决此问题。
- 近丘过高会吞掉中景，低矮残片靠近镜头后也会显得像完整方块。本轮降低右侧近丘、拓宽通道渐变，并将残片露出高度压到约 23–37 单位，保留主体远近层级。这些是当前视角观察，不是适用于所有布局的最优参数。
- 相机位置相对同一谷地中轴采样，眼高相对真实地形高度。桌面与移动网格分别做轨迹净空检查，避免降采样后通道局部抬高而穿地；前 20% 的位置、注视点、视角和滚转保持不变。
- 用路由内 DOM 的 `:has()` 选择器隐藏根滚动条外观，保留原生文档高度；底部细线读取原生进度，GSAP 的短暂追随只影响相机进度。没有拦截 wheel 或用进度条接管输入。

## P1-A3 反馈后的修订

- 首轮独立椭圆丘脊仍产生重复的凹口，不能把“一个高度网格”误认为视觉上已经连贯。当前坡脊沿纵深连续插值，彼此平滑融合；两处交叠丘面在连续沙体上塑形，保留层次，避免每个丘包单独降到谷底。
- 左侧两条坡脊间用两种实际地形网格采样连接带；最低连接高差约 97.96 单位，高于谷底。此数值是当前布局的有限采样结果，不是对任意参数的连续性证明，也不能替代画面评审。
- 前 20% 静止段会让用户误以为没有响应。已取消，起点前移，首端使用非零位移导数，短暂进度追随改为 0.18 秒；有效滚动长度为首次视窗高度的 3 倍。
- 固定垂直 FOV 会在窄窗裁去两侧。按参考画幅计算垂直 FOV 后，468 次可见建筑顶点对照均保留了原水平投影与画幅内位置；仍需浏览器检查取景，不能把这个投影检查当作艺术验收。
- 仅修正 FOV 还不够：若文档始终以实时 vh 计算总长度，改变窗口高度会改变同一 scrollTop 的旅程进度。当前将本次访问的原生滚动距离固定为像素，只让粘性画布跟随实时视窗高度；无需在 resize 时重设滚动位置。

## P1-A4 实际技术补充

- 低矮遗构直接沿旋转后的顶面采样地形，以最大露出高度放置整个实体；沙丘网格负责遮挡，未裁切或隐藏模型。浏览器首轮暴露出左横梁过于完整的问题，随后改变位置、朝向和露出量，而非机械采用埋深百分比。
- 单一巨柱的前面用带孔平面与五个凹槽内面形成闭合边界。体积、拓扑及射线检查分别确认真实凹陷、朝外绕序与完整顶冠；没有叠一条深色面冒充结构切缝。凸形构件沿用既有阴影策略，凹槽巨柱接收阴影。浏览器发现旧阴影视锥裁掉新巨柱上部后，扩大固定覆盖范围，并验证巨柱顶点均位于视锥内；没有增加动态阴影跟随系统。
- 路径绕过第三块斜板，遮挡不由显隐动画驱动。离线以变换后的实际三角形采样射线，记录巨柱前面九点被遮挡及恢复的区间；这只描述该取样面域，不能当作每个像素或连续运动的证明。最终仍以浏览器原生滚动检查空间叙事。
